Architecture

Local control, explicit boundaries.

The Agent is the control plane. Protocol defines contracts. Toolbox handles native data-plane work. Memory persists context. Assistant provides a resident runtime. AI Workers isolate heavier workloads. Reverse Proxy keeps browser-backed provider access behind its own trust boundary.

Web bridge

KITT Reverse Proxy

A dedicated authorized browser/API gateway and session bridge for provider access that needs to remain outside the Agent's core process.

This is especially useful when a provider workflow is available through an authenticated web session while direct API access is unavailable or undesirable. Browser authentication, provider sessions and security boundaries remain isolated in the gateway.

Active development. The reverse proxy is experimental and provider behavior can change.

Project principles

Designed for control, not lock-in.

The ecosystem favors measurable performance, explicit authority and components that can evolve independently without duplicating implementation.

01

Local-first

Remote providers are integrations, not the center of the architecture.

02

Fast hot path

Keep orchestration lightweight and move deterministic heavy work to native components when it materially helps.

03

Explicit authority

Agents act through capabilities, approvals and workspace boundaries.

04

Composable

Share contracts and namespaces instead of vendoring copies between repositories.

05

Bounded resources

Queues, frames, outputs and telemetry have explicit limits where practical.

06

Reviewable evolution

Self-improvement is evaluated and promoted explicitly, never silently self-deployed.
